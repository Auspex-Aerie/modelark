# ModelArk v0.3.3 — Public Alpha Patch

ModelArk v0.3.3 makes exact placement review recoverable across browser reloads, reconnects, and
other clients. It retains the schema-v7 catalog and is an application-only update from v0.3.2.

## What changed

- One immutable draft based on the current planner revision is now explicit `review_pending`
  operator-attention state.
- Opening the Fill page restores that exact stored review once, including its proposal ID,
  canonical seal, assignments, and backend-authored confirmation phrase.
- Start Fill is blocked in both the browser and execution service until the pending draft is
  approved or explicitly discarded.
- Discard marks only the named draft superseded; it does not change the active approval or planner
  revision and never moves archive bytes.
- Publishing a second current draft is refused, draft publication while Fill is live is refused,
  and historical multiple-current-draft state is reported as typed ambiguity.

## Upgrade from v0.3.2

No catalog migration is required. Stop the current service, retain its unit and runtime as rollback,
deploy v0.3.3 against the same explicit data, state, and config paths, and start without automatic
Fill resume.

If v0.3.2 already stored a successor draft whose browser response was lost, do not create another
replacement proposal. Open the Fill page after upgrading; v0.3.3 will restore the existing review.
Approving it still does not start Fill. Start Fill separately only while an operator can respond to
its attended drive-loading prompts.

See [Operating ModelArk](../operations.md) for the replacement-drive workflow and
[Upgrading ModelArk](../upgrading.md) for the rollback boundary.

Usable Slice, scratch delivery, and peer-to-peer transport remain future direction rather than
features of this patch.
